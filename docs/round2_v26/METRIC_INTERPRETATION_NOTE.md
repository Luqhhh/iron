# V26 指标解释更正，原实验保留

2026-10-04追加。原[预登记](PREREGISTRATION.md)中“log-target MSE对应指标自身逐行相对误差权重”的动机解释不成立。原文、配置、训练源码、结果与失败决定均保持原字节；本说明不追溯改判或重跑V26。

本仓库实际指标为

`WMAPE = Σ|y−prediction| / Σ|y|`。

对一个固定目标及固定评价分区，分母是常数，所以最小化WMAPE与最小化原单位MAE等价。每一单位绝对误差对分子的贡献相同。它不同于`MAPE = mean(|y−prediction|/|y|)`，后者逐行除以该行目标。

例如目标为[10,100]，预测A=[11,100]、B=[10,101]：两者WMAPE均为1/110，但MAPE分别为1/20和1/200。仓库真实`metrics.wmape`在锁定Python3.12中与独立有理数结果一致；V26评分调用的`v5_resolution.wmape`委托给同一实现。

此外，原单位MSE按误差平方惩罚行，不是仅因目标较大就增加权重。正目标附近，log空间平方误差近似为`(prediction−y)²/y²`；它既不是WMAPE，也不是MAPE。非线性目标变换可以作为不同统计假设探索，但不能以“与WMAPE逐行权重对齐”作为理由。当前MAE/Huber等具体实验的既有失败也不因此改判；优化指标与泛化收益是不同问题。

本次没有修改评分函数，也没有重新审计V26旧预测和数值结果；已确认源码实际计算聚合WMAPE，更正范围仅为上述文字动机。私有反例收据及原文件摘要在`local/runs/metric-interpretation-review-20261004/review-r1/`。0官方数据读取、0拟合、0预测包、0桌面写入、0助手上传。下一阶段不据此重开原log/sqrt配方。
