## 固定执行流程

1. `freeze`：只读元数据和输入字节摘要，冻结算法、实际 cutoff 与 eligible IDs。
2. `prepare`：在 8/1、9/1、10/1、11/1 四个训练截止点，分别训练 E09/E04 并
   预测同一批 November 样本；仅用开发标签，16 次单目标 fit。
3. `report`：校验预预测身份后一次读取合法 November 标签，对四场景出具报告。
   无 challenger 时保持先前冻结 C_ref，不虚构二选一胜者，不因报告差而修改算法。
   四场景只对应一个保护月份；消费后 November 不再 untouched。
4. `final`：独立授权，校验前序报告及账本后读取全部合法官方训练标签，
   4 次单目标 fit。训练与历史 cutoff 一致；公共过程数据仍按每条参考时刻推进。
5. `predict`：独立恢复完整组合，不读取官方标签文件、不调用 fit；保存阶段映射，
   核验原始预测重复一致、CSV/ZIP 回读、三列与 sample_id、有限非负数及摘要。
   正式评分按 sample_id 对齐；内部顺序一致检查只是额外工程保证。

入口为 `python -m bf_tap.optimization.final_lifecycle`，所有实际命令均使用
`uv run --locked --python 3.12`。各步骤使用新目录，不覆盖原产物。
本次不自动上传平台或推送 Git；原 E16 包及其 SHA256 保留。
