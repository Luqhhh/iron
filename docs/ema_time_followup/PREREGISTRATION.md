## 冻结设计

配置 `configs/ema_time_followup/SPEC.json` 固定三个探针和一个列组合控制；在读取新评估结果前冻结候选池与权重，不进行密集扫描。使用原始 V32、原始 EMA 全量 checkpoint 和原始 V7 全量模型，全部复用，不训练、不消耗新 split seed。

令 `T(q)=V32_time + q*(EMA_time - V7_time)`。已测 q=0 的 V32=96.3727，已测 q=0.5 的 EMA=96.3895。新增 q=0.25、0.75、1.00，用来检查收益是否在中间饱和、增大替换强度是否继续有效。三者铁量均保留 V32 原字符串。

**q 大于 0.5 是组件层面的仿射外推。** 分解为 `0.2*V36 + 0.3*N0048 + (0.5-q)*V7 + q*EMA`，因此 V7 系数为负；不得称为凸融合。若任何预测不有限或为负则拒绝该实验，不新增裁剪等后处理。q=0.5 必须精确重建已测 EMA 原 CSV，此参照不生成重复提交包。

第四项 DE3_IRON_EMA_TIME_Q50 逐字段复制已测 DE3 包的铁量和已测 EMA 包的时长，验证两列收益的可叠加性。条件算术 `96.3895 + (96.3749-96.3727)=96.3917` 仅来自用户回传分数及两列等权评分；它不是已测组合分数，也不是独立核验的预测。
