# RealMLP 原生 MAE 的后续接口准备

本文件不启动新科学拟合，不改变正在运行的MSE四切分确认或条件全量发布。持续优化目标仍为96.45。现RealMLP配方用作者默认MSE训练、MAE选轮；平台绝对误差目标提供检验训练损失一致性的机制理由，不能据此推断收益，亦不能把其他网络上的MAE失败扩大为整个RealMLP家族失败。

查阅已冻结的pytabkit1.7.3作者源码：`NNCreator.get_criterions`在`train_metric_name=None`时回归默认MSE；指定`mae`时调用作者`Metrics.apply`。准备器只在原TD的constructor/resolved同时新增`train_metric_name='mae'`，原V9训练器、网络、学习率、衰减、batch、调度跨度、预处理、原生输出限制、MAE选轮与最后最佳轮规则不改。调整训练损失会改变梯度尺度，原学习率不保证仍合适，固定这一配方的失败不否决家族。

本次验证范围限原生配置解析及两行合成张量的损失/梯度。构造一个未拟合sklearn包装器，0神经网络、0fit、0optimizer、0数据/标签读取、0预测、0确认seed、0包。单数值及torch线程1，锁定Python3.12/既有CPU环境，不同步依赖。

后续须单独冻结MAE合成原生对照/捕获/冷读的工程预算，再冻结两个完整开发split及固定候选、参照和拟合预算。原生MAE工程未通过前不读取新科学结果或开始该路线；本批没有确认/最终seed资格。当前MSE确认按原协议完成；本准备不以局部确认结果选择路线、改权重或增加平台队列。
