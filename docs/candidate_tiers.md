# 后续候选双轨分类（candidate-tiers-v1）

本文保留 `candidate-tiers-v1` 的机器分类口径，供 `bf_tap_r2.candidate_tiers` 兼容使用；下面的两切分/折门槛是该分类器的原合同，不等于后续科学拟合的全部正式晋级条件。历史 V2.1/V2.2 决定和已交付包不改，分类不新增拟合。

## 当前晋级与平台探索边界（2026-10-01）

新科学拟合依 [AGENTS.md](../AGENTS.md) 与阶段冻结协议：至少四个完整 split seed、各 seed 收益均正、seed 层配对 LCB95 > 0，fold 层仅描述；不能仅凭旧分类器输出 `formal` 声称已通过这些要求。参照在评估前从 `round2_current_platform_best` 冻结，已冻结阶段不换锚点。

**本地收益不能作为唯一平台筛选指标。** `not_shortlisted` 或正式未晋级不等于已证明平台无效；有明确机制和信息价值的探索可在具体用户授权下预登记，不修改原分类或失败条件。自动探索推荐每轮跨目标最多一个；用户指定诊断例外只限相应批次。

人工排程优先有依据的较大收益或重要信息问题，小幅且相似的包降低优先级，不为用完额度安排测试。DE3＋Q75 当前仅作替补、暂不平台测试；具体队列见状态文件，不用下文旧 AJ3 参照。

## 冻结分类器口径

- 正式晋级 `formal`：沿用两组完整 OOF 均改善、至少 7/10 折改善、任一铁口 WMAPE 退化不超过 0.001 的门槛。每目标最多推荐一个，按平均 WMAPE 选择；1e-6 内按事先登记的低成本优先顺序选择。
- 探索候选 `exploration`：平均 OOF 相对当前目标参照改善超过数值容差 1e-12，但未通过一项或多项稳定性门槛。完整保留未通过条件、两组收益、折改善数和最差铁口退化，不授予正式晋级资格。
- 不入围 `not_shortlisted`：平均 OOF 没有改善。保留记录，不标注为“已证明无效”。身份错误、缺失指标、非有限指标属于证据错误，直接停止，不能降级成探索候选。

每轮探索推荐最多 **1 个（跨两个目标合计）**。按平均改善降序，再按最小跨切分改善降序，完全相同时按目标名、候选名排序；其余探索候选保留在报告中。正式候选优先，按最小跨切分改善排序。没有正式候选时，探索候选仍可作为待验证方案；额度不足时顺延，不为用完额度自动发布。

分类报告是开发短名单，不自动生成提交包、不修改 incumbent、不调用平台。发布仍需数据/模型摘要核对、同验证折 OOF 检查、独立回读复核和冷推理检查；未修改的目标列复制当前父包的 CSV 字符串。探索候选只做单目标平台验证，平台回传后再决定是否替换当前包。用户自行上传并回传，每天上限 5 次，不重复询问上传方式或额度。

配对重采样仅描述冻结 OOF 对样本组成的敏感性，不作为新增淘汰门槛。该探索机制允许保留部分本地均值为正但不稳定的候选，不能保证降低实际误淘汰率、捕获本地负而平台正的候选，或证明候选有效；这类平台探索须按当前授权另行登记。

## 平台迁移证据补充（2026-10-04）

SiLU A100出现完整两split正收益、用户回传平台负收益后，已完成[联合输入、同查询重训及322行敏感性诊断](platform_transfer_diagnostics/RESULTS.md)。两个固定域分类器没有解释该反转，OOF均值排序也未体现A100的行组成敏感性。此结果不证明A20会获胜，不能新增事后数值否决门。

后续候选的人工平台排程附[迁移证据记录](platform_transfer_diagnostics/REVIEW_TEMPLATE.md)，同时呈现完整OOF、样本组成敏感性、发布训练改变量、相关平台机制反例及未验证项；冻结方法和排程理由在新反馈前保存。缺失证据须写明，不能为填卡自动重训。机器输出的`submission_priority`仍只是开发短名单，不能直接解释成平台成功概率或平台最优排序；正式四seed门、原分类器、历史选择规则和每轮自动探索上限均不变。

## 平台测试优先级补充（2026-09-23，用户指定）

目前已回传的 V2 Top 5 中，平台分数与本地 OOF 分数相差约 0.09～0.11 分，绝对差异总体不大；但对于分数接近、提升较小的候选，差异足以改变排序。这里指小幅收益候选的名次不稳定，不是“低分模型才会排序混淆”，也不保证其他候选仍具有相同偏差。

后续平台测试包优先选择相对当前目标参照有较大离线提升，或者具有明确、重要探索价值的方向；仅有小幅提升、与已测方案高度相似的包降低优先级，不为凑包数量或用完每日额度安排测试。探索价值须说明具体要验证的问题、已有证据与验证成本，不能仅凭路线名称新颖。该补充撰写时的历史参照为 AJ3 铁量／完整 B3 时长、96.1259；后续参照从 `EVIDENCE_STATUS.json -> round2_current_platform_best` 冻结。

本补充用于人工发布与平台排程，优先于仅按 formal/exploration 标签安排上传的旧表述；不修改自动分类函数、冻结门槛、探索推荐上限或历史结果。小幅提升仍保留证据与原分类，降低优先级不等于认定无效或永久排除。暂不新增“大幅提升”的数值硬门槛；若后续阶段需要，应在评估前明确冻结。不得给本地分数统一加偏移作为平台预测。

## 分类器接入示例（不替代当前四切分晋级协议）

下一轮必须在看结果前冻结候选池、每目标当前参照和低成本平局优先顺序。沿用 metrics 的 `target -> route -> split -> wmape/by_fold/by_spout` 格式。阶段 YAML 包含：

```yaml
split_seeds: [42, 3407]
folds: 5
reference_by_target:
  tap_iron: CURRENT_IRON
  tap_time_len: CURRENT_TIME
candidates:
  tap_iron: [IRON_CANDIDATE]
  tap_time_len: [TIME_CANDIDATE]
tie_preference_by_target:
  tap_iron: [IRON_CANDIDATE]
  tap_time_len: [TIME_CANDIDATE]
```

使用真实冻结阶段文件替换以下占位路径：

```bash
uv run --locked --python 3.12 --extra round2 python -m bf_tap_r2.candidate_tiers \
  --metrics local/runs/NEXT/selection/summary.json \
  --spec configs/NEXT/experiment.yaml \
  --policy configs/candidate_tiers.yaml \
  --output local/runs/NEXT/selection/candidate-tiers.json
```

命令只读取已生成的指标，不训练；输出限制在 `local/`，已存在文件拒绝覆盖。新阶段评估器也可直接调用 `classify_candidates`。旧 `choose_c2()` 和 `choose_targetwise()` 保留历史含义，不自动切换规则。
