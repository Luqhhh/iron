## 独立处置计划（本轮不执行远端变更）

1. 经明确批准后优先限制外部访问，并核查协作者、fork、Pages/发布附件、Actions 保留与下载权限；转私有本身不等于撤回既有 clone/下载。
2. 原代码、refs、Git bundle、既有模型/预测/报告/账本留在授权私有环境。保存内容哈希、旧 commit/tag 身份和获取时间；不删除失败证据。
3. 在隔离副本制定数据移出/历史清理或迁移方案。逐项清点分支、标签、PR refs、Actions 日志和 artifacts；清理前审核清单与保留策略。禁止在当前工作目录盲目 force-push。
4. 若产生新历史，保存旧 SHA 到新 SHA/文件内容身份的映射，冻结基线旧身份在私有存档中保留，不伪装为原 tag 未变。协调协作者重新同步，防止旧历史再次推回。
5. 针对可处理的缓存/ref 联系 GitHub 支持，按实际能力记录已处理和不可撤回范围。恢复公开发布前，只发布审查通过且不含赛事数据历史的代码/汇总，并验证可复现证据仍可在私有环境追溯。

[GitHub 官方历史清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)指出旧副本和相关引用需另行协调处理。本文是处置计划，不表示已经改变可见性、清理远端或消除了传播风险。
